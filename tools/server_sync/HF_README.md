# Hugging Face Desk

통합 `sync_server_ui.sh`의 **Hugging Face 탭**입니다. 서버 간 전송과 같은 포트에서
화면 구성·작업 큐·취소 기능을 쓰고, 실제 동기화는 기존 `hf_sync.py`로 실행합니다.
선택 항목 삭제는 별도 Hub 삭제 작업으로 실행합니다.

## 실행

파일을 보내거나 받을 **서버에서** 실행합니다. GPU는 필요 없습니다.

```bash
bash sync_server_ui.sh
# 같은 UI를 여는 CLI 옵션
bash hf_sync.sh --web
```

VSCode Remote SSH의 Ports에서 **8765**를 전달하고 Hugging Face 탭을 엽니다.
일반 SSH 터널을 쓰면 본인 컴퓨터에서 다음 명령을 실행합니다.

```bash
ssh -N -L 8765:127.0.0.1:8765 <사용자@서버주소>
# 브라우저: http://127.0.0.1:8765/hf/
```

`127.0.0.1`에만 바인딩합니다. 포트를 바꾸려면 `--port 8877` 또는 `SYNC_UI_PORT=8877`을
지정하고 그 포트를 전달하세요. 모든 탭은 같은 포트에 있습니다.
Python은 기본 `.venv/bin/python`, 없으면 `python3`이며 `SYNC_UI_PYTHON`으로 지정할 수 있습니다.
Python 3.10+, `huggingface_hub`, 기존 설정 로더의 `pyyaml`이 필요합니다.

```bash
hf auth login  # 서버에서 한 번; 또는 HF_TOKEN 환경변수
bash sync_server_ui.sh --server runpod --port 8765 --concurrency 2
# 저장소 변경 (기본: global_config.yaml / SBD_HF_*_REPO)
bash sync_server_ui.sh --repo my-account/my-data --checkpoint-repo my-account/my-checkpoints
```

인증 토큰은 서버에서만 사용하며 브라우저에 전달하지 않습니다. 상단의 토큰 표시는
설정 유무이며, 토큰 만료·저장소 권한·gated 모델 이용 동의는 실제 Hub 요청에서 확인됩니다.
통합 UI 실행 시 셸에서 상속된 프록시 설정은 자동 제외됩니다. 기존 HF 로그인은 그대로 사용합니다.

## 사용

1. 작업 메뉴에서 데이터셋 다운로드/업로드, 모델 다운로드, 체크포인트 다운로드/직접 업로드를 고릅니다.
   데이터셋과 체크포인트는 가운데 **⇄** 버튼으로도 방향을 바꿀 수 있습니다.
2. 폴더 이름으로 이동하고 체크박스로 필요한 파일·폴더를 담습니다. 선택은 폴더를 이동해도
   유지되며, 작업 종류를 바꾸면 비워집니다. 검색은 현재 폴더의 항목 이름을 대상으로 합니다.
3. **전송 준비**에서 서버 경로와 Hub 경로를 확인하고 **시작**을 누릅니다.
   준비만으로는 전송하지 않습니다. 상위 폴더에 포함된 중복 선택은 합칩니다.
4. 작업 상태에서 상세 로그를 열거나 실행·대기 항목을 취소할 수 있습니다.
   HF가 출력하는 퍼센트는 파일별 진행률이므로 UI의 전체 작업 완료율로 표시하지 않습니다.
5. **미리보기 실행**을 체크하면 CLI의 `--dry-run`으로 계획만 출력합니다.
   Hub 목록·경로 조회는 할 수 있지만 파일 업로드·다운로드·삭제는 하지 않습니다.

데이터셋 루트는 기존 CLI와 같이 `dataset` / `dataset_*`만 지원합니다. 모델 목록은
`hf_sync.py`의 `PRETRAINED_MODELS`를 그대로 사용하며 모델은 원본 저장소에서 받습니다.
데이터셋·모델의 저장 위치는 storage volume 설정을 따르고, 체크포인트는 프로젝트의
`outputs*`에 받습니다. 체크포인트 다운로드 후 `checkpoints/last`와 `.hf_pulled` 처리도
기존 CLI와 같습니다. 여러 체크포인트 다운로드는 공유 메타데이터가 충돌하지 않게 순차 실행합니다.

**체크포인트 업로드 · 직접 선택**에서는 서버의 `outputs*`를 탐색해 숫자 체크포인트
폴더 또는 모델·상위 폴더를 선택합니다. 상위 폴더를 고르면 `checkpoints/last`가 가리키는
완료 시점까지의 숫자 체크포인트만 펼쳐서 확인 화면에 표시합니다. `last` 링크와 아직
저장 중인 step은 전송하지 않습니다. 가중치와 optimizer/scheduler/RNG 상태를 원래
상대 경로대로 공개 체크포인트 저장소에 올립니다. 자동 감시·보관 개수 정리·로컬 삭제는
실행하지 않습니다. **체크포인트 자동 업로드**는 별도 작업으로 그대로 제공합니다.

PT·FT 평가 폴더에서 `bash submit_eval.sh --prepare-runpod`를 실행하면 없는 체크포인트를
공개 저장소의 원래 경로에 업로드합니다. 평가에 필요한 `pretrained_model`만 보내며
optimizer 등 `training_state`는 제외합니다. 일반 직접 업로드는 기존처럼 전체 체크포인트를 보냅니다.

## Hub 파일 관리 · 삭제

작업 메뉴의 **HF 데이터셋 관리 · 삭제** / **HF 체크포인트 관리 · 삭제**에서
설정된 저장소의 파일·폴더를 탐색하고 삭제할 수 있습니다.

1. 삭제할 파일·폴더를 체크하거나 **현재 폴더 담기**를 누릅니다.
2. **삭제 준비**에서 저장소, 선택한 경로, 내부 파일 수·용량, 파일 목록 일부를 확인합니다.
3. Hub에서 삭제한다는 확인란을 체크하고 **Hub에서 삭제**를 누릅니다.
4. 작업이 끝나면 목록이 갱신됩니다. 삭제한 폴더 안을 보고 있었다면 실제로 남아 있는
   가장 가까운 상위 폴더로 이동합니다. 빈 폴더는 Hub에서 표시되지 않으므로 여러 단계가
   함께 사라질 수 있으며, 상위 폴더가 모두 비면 저장소 루트로 돌아갑니다.

**미리보기 실행**을 켜면 대상과 계획만 출력합니다. 실제 삭제는 하지 않습니다.
미리보기는 10분간 유효하며 확인한 선택과 일치하는 요청만 실행할 수 있습니다.
확인 당시의 저장소 버전에 파일 목록을 고정하고, 이후 업로드 등으로 저장소 버전이
바뀌었으면 삭제를 실패 처리합니다. 이때 목록을 새로고침하고 삭제 준비부터 다시 진행하세요.

- 삭제 대상은 설정한 데이터셋 저장소의 `dataset` / `dataset_*`, 체크포인트 저장소의
  `outputs` / `outputs_*` 내부 파일입니다. 로컬 파일, 저장소 자체, 원본 사전학습 모델 저장소는 삭제하지 않습니다.
- 선택한 폴더 아래의 원격 파일은 전부 삭제됩니다. 상위·하위 중복 선택은 합칩니다.
- 삭제 기록을 포함한 Hub 커밋 이력은 유지합니다. 따라서 파일을 삭제해도 사용 중인 Hub
  저장 용량이 즉시 줄지 않을 수 있습니다. 이 기능은 저장소 이력을 자동 압축하지 않습니다.
- 같은 UI의 자동 업로드가 해당 저장소에 실행 중이면 충돌을 막기 위해 먼저 중단해야 합니다.
  자동 업로드를 다시 실행하면 로컬에 남은 체크포인트가 재업로드될 수 있습니다.
- Hub에 이미 전송된 삭제 요청은 취소하더라도 적용될 수 있습니다. 작업 상태가 불분명하면
  원격 목록을 새로고침해 확인하세요. 파일 삭제 권한은 로그인한 HF 계정·토큰 권한을 따릅니다.

## 자동 업로드

**체크포인트 자동 업로드**에서 감시할 루트, 간격, 최근 보관 개수, 보호 step을 설정합니다.

- 기본: 모든 `outputs*`, 300초 간격, 전부 보관, 로컬 삭제 끔.
- 최근 보관 개수가 1 이상이면 오래된 Hub step을 삭제합니다. 보호 step은 남습니다.
- 로컬 보관 규칙과 Hub 기록 압축은 체크했을 때만 켜집니다. 삭제 범위는 시작 전 다시 표시합니다.
- 한 번만 확인, 미리보기 실행을 지원합니다. 미리보기는 한 번 확인 후 종료합니다.
- 저장 완료 여부, 내려받은 step 제외, 라이선스 처리 등은 `hf_checkpoints.py`를 그대로 사용합니다.
- UI에서 Pod 자동 종료는 활성화하지 않습니다. 필요하면 기존 CLI의 `--done-step` / `--done-time`을 사용하세요.
- yonsei처럼 기존 학습 결과가 많은 서버에서 자동 업로드를 시작하면 해당 루트의 기존 완료
  체크포인트도 대상입니다. 루트를 지정하거나 먼저 미리보기로 계획을 확인하세요.

브라우저를 닫아도 전송·감시는 계속됩니다. UI 서버를 Ctrl+C로 종료하면 실행·대기 작업도
취소됩니다. 대기열·로그는 메모리에만 저장되므로 서버를 재시작하면 사라집니다.
SSH 연결을 끊은 뒤에도 유지하려면 tmux 안에서 실행하세요. 취소한 전송은 다시 준비해서
실행할 수 있고, 이미 받은 파일·업로드한 데이터는 기존 HF 캐시·중복 제거 규칙에 따라 재사용됩니다.
